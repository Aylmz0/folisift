# Architecture

Folisift is a Rust workspace that turns source PDFs into Turkish, paper-like,
exam-oriented study guides. The guide bundle is the unit of content; the engine
never knows a course name, a source filename or a slide count.

## Layers

```text
sources/                      local PDF inputs (gitignored)
    │
    ▼
folisift-parse                liteparse inventory, coverage, screenshots
    │
    ▼
folisift-render               Markdown + directives → Typst → PDF
folisift-build                shared CLI/MCP build orchestration and gates
    │
    ▼
guides/<slug>/                guide.md + config.json + visual-audit.json +
                              diagrams/ + assets/ + data/
    │
    ▼
folisift-cli / mcp            CLI and stdio MCP tools
```

| Layer | Path | Responsibility |
|---|---|---|
| Core | `crates/folisift-core/` | Config/schema, workspace sandbox, scaffold, version. |
| Parse | `crates/folisift-parse/` | liteparse adapter, inventory, coverage, screenshots, visual candidates/assets, visual-audit validation. |
| Render | `crates/folisift-render/` | Markdown/directives, style registry, Typst world, PDF. |
| Build | `crates/folisift-build/` | Shared build orchestration and gates for CLI/MCP. |
| MCP | `crates/folisift-mcp/` | stdio tools, resources and prompt. |
| CLI | `crates/folisift-cli/` | `folisift` binary. |
| Templates | `templates/paper.typ`, `clean.typ`, `revision.typ` | Engine-owned layouts; paper is the legacy parity layout, revision is the exam-revision/organiser layout. |
| Guide | `guides/<slug>/` | Content, config, assets, generated data. |
| Inputs | `sources/` | Original PDFs; local only. |
| Outputs | `output/` | Generated guides for review. |

## Build flow

1. `folisift build --guide <slug>` loads `guides/<slug>/config.json`.
2. Paths resolve relative to the guide directory and are checked against the
   workspace root.
3. `folisift-render` resolves the style pack (`styles/<id>/`) and parses
   Markdown + YAML frontmatter, `::: diagram` references and the
   layout/content
   directives (`front`, `toc`, `chapter`, boxes, `must-know`, `synthesis`,
   `answer`, `organiser`, `table`, `glossary`, `columns`, `columnbreak`,
   `pagebreak`).
4. The Typst template renders the PDF with embedded fonts.
5. Visual assets are resolved before render: native images live under
   `data/figures/`, page crops under `data/crops/`; both are local-only and
   hash-checked. `::: figure` requires `src`, `caption`, `alt` and `source`.
6. `--check` compares the inventory with the Markdown headings and section
   bodies, then writes `data/coverage.md`. Revision sheets use their own
   grammar gate instead of A–G coverage; knowledge organisers are one page per
   unit. See `docs/document-genres-and-layout-systems.md`.
7. The PDF is written to the configured output path.

Diagram assets are generated by `folisift diagram build` in the CLI using the
pinned D2 binary. The guide build and MCP read only the committed SVG and
manifest; they never execute D2. The MCP server wraps the same build
operations over stdio or streamable HTTP (`mcp --http`). It performs no LLM
call, no shell execution and no network access. The host agent writes content;
the server analyzes, renders and audits.

## Guide config (schema 3)

```json
{
  "schema_version": 3,
  "slug": "my-course",
  "title": "My Course — Study Guide",
  "language": "tr",
  "content": "guide.md",
  "output": "../../output/my-course.pdf",
  "sources": ["../../sources/source-a.pdf", "../../sources/source-b.pdf"],
  "inventory": "data/source.json",
  "coverage": "data/coverage.md",
  "target_pages": "18-22"
}
```

Rules:

- `content`, `output`, `inventory` and `coverage` resolve relative to the guide
  directory.
- `sources` are read-only inputs and must stay under `sources/`.
- No absolute paths. A guide must work after the repository is moved.
- `schema_version` 1 is rejected; schema 2 is the legacy Markdown shape and schema 3 is the current style-profile shape.

## Content format

Markdown + YAML frontmatter plus `front`, `toc`, `chapter`, `definition`,
`critical`, `example`, `note`, `table`, `columns`, `columnbreak` and
`pagebreak` directives. Source references use `[SOURCE, s. 3]`. Figures use
`::: figure src=… caption=… source=… alt=…`; the Typst template owns
numbering. Raw Typst/CSS in a guide is forbidden. The complete authoring
surface is in `docs/authoring.md`.

## Generated artifacts

| Artifact | Producer | Committed? |
|---|---|---|
| `guides/<slug>/data/source.json` | `folisift analyze` | yes; reviewable |
| `guides/<slug>/data/source.md` | same | yes; checklist |
| `guides/<slug>/data/blocks/<source>.json` | `folisift analyze` / `prepare_guide` | no; generated layout cache |
| `guides/<slug>/data/document-graph.json` | `folisift graph build` | no; generated review graph |
| `guides/<slug>/data/coverage.md` | `folisift build --check` | yes; audit trail |
| `guides/<slug>/data/coverage-manifest.json` | `folisift coverage-manifest --action build` + host review | yes when reviewed; authoritative gate input |
| `guides/<slug>/data/headings.review.md` | `folisift analyze` | yes; heading/TOC review aid |
| `guides/<slug>/data/incremental-sections.json` | `folisift build` | no; section-hash report |
| `guides/<slug>/visual-audit.json` | host author / `visual decision` | yes; low-text and figure decisions |
| `guides/<slug>/data/crops/` | `visual decision` / `crop-source` | **no**; local source crops |
| `guides/<slug>/data/figures/` | `visual extract` / `visual decision` | **no**; local native images |
| `data/cache/` | `folisift analyze` / `read_source` | no; source text cache |
| `guides/<slug>/data/pages/` | `folisift render-pages` | no; visual cache |
| `output/*.pdf` | `folisift build` | no; local review artifacts |
| `sources/*.pdf` | instructor/user | **no**; gitignored |

## Coverage model

The inventory is the mechanical checklist: sources, pages, headings and
low-text pages. The gate checks that every top-level numbered section has a
matching normalized heading in the guide. It is deliberately conservative: a
missing number is reported, never guessed.

The guide’s G section is the human audit: tables, figures, examples, low-text
pages, exclusions and inaccessible content. The automated gate cannot claim
completeness on its own.

## Testing

```bash
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo run -p folisift-cli -- build --guide pd0-pd1 --check
```

The Rust tests cover path safety, config validation, Markdown directives,
inventory/coverage logic, visual candidate/score/classify/quality logic,
visual-audit provenance and a minimal Typst render. The MCP server is probed
with a stdio client during release checks.

## Source visual workflow

1. `folisift visual candidates --source sources/<file>.pdf --pages … --write`
   returns ranked, text-only candidates with bbox, context, `relevance`,
   `reconstruction`, `score_parts`, `suggested` and `review_mode`, and upserts
   `data/visual-candidates.json`.
2. The host reads the bounded context and decides: embed native, embed crop,
   redraw with D2, use a table, describe or skip.
3. `folisift visual decision …` materializes the asset, validates quality,
   upserts `visual-audit.json` and prints the exact Markdown snippet. It never
   edits `guide.md`.
4. `folisift visual assets --guide <slug> --action check|materialize|refresh`
   verifies or regenerates recorded assets.
5. `folisift build --guide <slug> --check` enforces the visual gate. Gated
   pages come from the candidate manifest; `warn` reports `advisory`, while
   `required` needs the manifest and blocks missing decisions.

The MCP equivalents are `visual_candidates`, `visual_extract`,
`visual_decision` and `visual_assets`. The boundary decision is
[ADR-0015](adr/0015-source-visual-pipeline.md). D2 remains a concept/schematic engine,
not a plotting library. Native images and crops stay local; source PDFs are
read-only.

## MCP guidance

The MCP contract is layered: a short server instruction, tool descriptions and
JSON Schemas, structured results with a concise summary, user-invoked prompts
and on-demand resources. See [MCP guidance](mcp-guidance.md). The server never
executes a shell, a network request or an LLM call.

Normative resources (`folisift://authoring-spec`, `folisift://design-system`,
`folisift://diagram-rules`) are embedded at compile time with `include_str!`,
so an installed binary works without a repository checkout. A workspace copy
at the same `docs/` path overrides the embedded text; the resource `_meta.source`
field reports `workspace` or `embedded`.

## Non-goals

Folisift is not a PDF library, an LMS, a quiz generator or a replacement for
the course. It is a repeatable authoring pipeline with an auditable output.
