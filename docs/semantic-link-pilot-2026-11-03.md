# Semantic link pilot — 2026-11-03

- **Status:** Pilot complete on two corpora; threshold decision recorded
- **Corpora:** PD0–PD3 (first corpus) and PD4–PD8 (second, formula-heavy
  parsing/semantics chapters) local course PDFs
- **Model:** `potion-multilingual-128M-int8`
- **Method:** LiteParse blocks → page-aware sections → Turkish BM25 candidates →
  model2vec cosine → filtered top-k links
- **Claim policy:** a link is a reading proposal, not a factual or causal
  verdict. The author must inspect the cited pages.

## 1. Setup

The pilot used temporary workspaces with the source PDFs. Layout blocks were
generated by `folisift analyze`. The initial review used the wider setting:

```bash
folisift links build --guide <slug> --model-dir models/potion-multilingual-128M-int8 \
  --top-k 8 --min-cosine 0.65 --min-score 0.45
```

The final default and `--explore` counts use the filters described in section
4. The reviewed sample is the top 20 links by combined score. Section text and
source pages were inspected before assigning a verdict. `useful` means "the
author should read these two sections together"; it does not mean the model
verified a fact.

and treat the semantic list as a checklist, not a reading order.

## 4. Failure patterns

1. **Repeated slide titles.** The same title on several slides produces
   same-heading links. The builder skips identical headings within one source.
2. **Adjacent slides.** Page-neighbour links are serial navigation, not a
   connection. The builder skips same-source links with page distance ≤2.
3. **Repeated slide series.** Slide numbers change the heading (`(6)`, `(9)`,
   `(10)`), so the builder compares heading tokens after dropping digits and
   skips the series within 10 pages.
4. **Shared bibliography/boilerplate.** Cross-source sections with the same
   heading and ≥80% text overlap are duplicated material, not a connection.
5. **Duplicate targets.** A section can be the top match for several nearby
   targets. The builder keeps one near-duplicate target and one edge per page
   pair.
6. **Broad course-intent sections.** "Amaç" and "Neden bu ders?" sections
   match many things weakly; the author should ignore these.
7. **Formula-heavy decks.** Serial shift-reduce examples and formula lines
   that LiteParse treats as headings still dominate the false positives. A
   higher cosine threshold does not remove them because their text is nearly
   identical.

## 5. Threshold decision

Observed counts after the final structural filters:

| Thresholds | PD0–PD1 | PD2 | PD3 |
|---|---:|---:|---:|
| default `0.75 / 0.55`, top-k 5 | 66 | 2 | 29 |
| `--explore` `0.65 / 0.45`, top-k 8 | 245 | 44 | 114 |
| pre-filter review sample `0.65 / 0.45`, top-k 8 | 271 | 45 | 135 |

Second corpus (PD4–PD8, 727 sections):

| Thresholds | Links |
|---|---:|
| default `0.75 / 0.55`, top-k 5 | 196 |
| `0.78 / 0.58`, top-k 5 | 128 |
| `0.80 / 0.60`, top-k 5 | 95 |

Raising the threshold cut the tail but did not change the top-20 sample: the
false links score above 0.92 because their text is duplicated. Threshold
tuning is therefore not a substitute for the structural filters.

Decision:

- Keep the default **`min_cosine = 0.75`, `min_score = 0.55`, top-k 5** for
  precision.
- Use `--explore` (`0.65 / 0.45`, top-k 8) only for a wider review list; it
  produces many weak and duplicate candidates.
- Do not lower the default until a larger hand-checked sample shows a better
  precision/recall trade-off.
- Keep source/page/block provenance and the `SIMILARITY` confidence label.
- Keep links review-only; a formula-heavy deck did not meet the 15/20 quality
  bar.

## 6. Remaining work

- Improve LiteParse heading acceptance for formula-heavy slides; the link
  helper should not need to compensate for parser artefacts.
- Repeat the hand-check on a third, prose-heavy corpus if one becomes
  available.
- Do not auto-insert links into guide prose; the author still chooses every
  connection.
