# ADR-0006: Build the v2 product as a Rust CLI and MCP server

- **Status:** Accepted
- **Date:** 2026-10-26
- **Deciders:** Maintainer

## Context

The Python engine is a working reference: it builds the 22-page PD0–PD1 pilot
and passes the coverage gate. It is not a good distribution unit for MCP
clients because it needs Python, Poppler and WeasyPrint. The product goal is a
local server that OpenCode/Codex can start with one command, plus a CLI for
humans.

## Decision

Build the v2 product in Rust as one workspace:

- `folisift-core` — config, schema, paths, version, scaffold.
- `folisift-parse` — source parsing, inventory, coverage, screenshots.
- `folisift-render` — Markdown to Typst to PDF.
- `folisift-mcp` — stdio MCP tools/resources/prompts.
- `folisift-cli` — the `folisift` binary.

The MCP server performs deterministic work only. The host agent/LLM owns
reasoning, structure and prose. The Python engine remains the reference until
the Rust path reaches content and coverage parity.

## Consequences

- One toolchain and one test command for the v2 path.
- The binary still needs the PDFium sidecar (ADR-0005); “one file” is not a
  goal.
- The Python reference must keep working until Phase 6; changes to shared
  content need a parity check on both paths.
- Rust compile times and binary size are real costs; measure them at release.
