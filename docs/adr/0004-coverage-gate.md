# ADR-0004: Coverage is a gate, not a claim

- **Status:** Accepted
- **Date:** 2026-10-25
- **Deciders:** Maintainer

## Context

The most common failure in long study guides is uneven coverage: the first
source gets deep treatment, later sources are summarised from memory. The
project needs a mechanical check before a build is called complete.

## Decision

Every guide has:

- an **inventory** (`data/source.json`) generated by
  `engine/tools/analyze_sources.py`;
- a **coverage report** (`data/coverage.md`) generated by
  `engine/tools/check_coverage.py`;
- a build command with `--check` that fails on missing top-level sections.

The coverage report checks section numbers and fuzzy heading matches. It does
not replace manual review of tables, figures, formulas and examples; those are
audited in section G of the guide.

## Consequences

- “Tam kapsam” is only claimed after `GEÇTİ`.
- A source without numbered sections needs a manual coverage note; the tool
  will not invent structure.
- The inventory is the single source of truth for page counts and low-text
  pages; do not hand-count.
- Builds are slightly slower when `--check` is used; this is intentional.
